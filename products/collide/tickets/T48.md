# T48 — F fits the canvas; collapse becomes the compact view

**Goal:** The `F` key fits the canvas, and the collapse button reduces the app to the compact view and swaps back to the full app.

**Source:** Grant, 2026-11-20 (the screenshot of the compact view). An unfinished attempt exists only on a local branch that is not in the repository: build from this ticket.

**Files in scope:** `app/src/editor/EditorShell.tsx`, `app/src/markdown/MarkdownEditor.tsx`, `app/src/pdf/PdfEditor.tsx`, `app/src/shell/*` (Shell, Sidebar, parts, shell.css), `app/src/native/collapse.ts` and tests, `app/src/native/bridge.ts`, `app/src/native/ipc.ts`, `app/electron/main.cjs`, `app/e2e*`, tests.

**Acceptance criteria:**
- The plain `F` key (no Ctrl, Alt or Meta) fits the canvas like Ctrl+0 does (Ctrl+0 stays). It works in the Snip editor, the Markdown Preview and on a PDF page. It never fires while typing in an input, textarea, select, contentEditable or a note being edited. First check `F` is not already a tool key; if it is, take the smallest option and mark (A). Add the key wherever Ctrl+0 is listed (tooltips, docs). Shortcuts stay provisional (ISSUES 10).
- The collapse button (the arrows next to "Collide") reduces the app to the compact view, and the same button swaps back to the full view. Compact view = the sidebar's top block only: brand row (logo, "Collide", the swap button, the Connected pill only if enabled), New snip with the delay, Add snip with Current/Behind, Open, New file. Hidden in compact: Search, Recents, Tags, the footer (Appearance, Settings), and the whole canvas and tabs, even when tabs are open. Tab state is kept and returns in the full view. The button shows Collapse or Expand (icon and aria-label).
- Desktop window: collapsing unmaximizes if maximized (remembered); the window becomes 276 px wide (`PANEL_WIDTH`) and exactly as tall as the compact block (the page measures it and passes the height), docked at the right edge of its screen, y kept but inside the work area. Expanding restores the exact earlier bounds and re-maximizes if it was maximized. Any minimum size on the window must not block the compact size and must come back on expand.
- This replaces the old rules "windowed with a tab open keeps its size" and "maximized keeps its size". Update only the assertions in `collapse.test.ts`, the ipc tests and e2e that encode the old rules, and list each in ISSUES.
- In a browser build the window cannot shrink: the page renders the compact block alone, top left.
- Keep the `collide.collapsed` pref and `window.__collide.state().collapsed`.
