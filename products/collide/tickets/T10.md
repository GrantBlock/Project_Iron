# T10 — Overlay window

**Goal:** Capture overlay UI: transparent, fullscreen, topmost window showing the frozen frame dimmed ~50%; dragged box at full brightness with a mono `W × H` readout; Esc cancels; release crops.

**Files in scope:** `app/src/overlay/**`, a second Vite entry or route (`overlay.html` or `#/overlay`), `app/src-tauri/tauri.conf.json` / window creation code, e2e tests.

**Acceptance criteria (from the board):** Overlay page runs in a browser with a fixture image; e2e drags in all 4 directions and gets a normalized box.

**Planner notes:**
- Look: `design-system/ui_kits/snip-markup/CaptureOverlay.jsx` — HUD copy "ESC TO CANCEL · RELEASE TO CROP", 1px dashed white selection with square corner handles, readout in Geist Mono with the × sign.
- In a browser the page loads a fixture via `?fixture=` or a test hook; in Tauri it gets the capture from T08. Emits `{ x, y, w, h }` normalized (positive w/h) in logical px via a callback/event; Esc emits cancel.
- Tauri window config: `transparent: true, decorations: false, alwaysOnTop: true, fullscreen` on the captured monitor, created hidden and shown by T11 (A).
- Readout reports physical pixels (logical × scale) so it matches the crop (A).
- From T09 (Planner decision, ISSUES #7): the overlay window must be exactly fullscreen on the captured monitor, origin at the monitor's top-left, because `crop_capture(x, y, w, h, scale)` takes overlay-relative **logical** px and multiplies by `scale` — no origin offset. Emit logical px; the readout shows physical (`round(w × scale) × round(h × scale)`).
