# T09 — Rust crop_capture

**Goal:** Tauri command `crop_capture(x, y, w, h, scale)` cropping the held frozen frame. x/y/w/h are logical (CSS) pixels relative to the overlay window; convert with the scale factor and monitor offset; return PNG.

**Files in scope:** `app/src-tauri/src/**`.

**Acceptance criteria (from the board):** Unit tests at 100/125/150/200% scaling, negative monitor origins, and zero-size boxes.

**Planner notes:**
- Pure function `crop_rect(logical, scale, monitor) -> Result<PhysicalRect>`: round outward consistently (floor origin, ceil far edge), clamp to the frame; zero-size or fully out-of-frame → typed error (not a panic).
- Negative origins: a monitor left of/above the primary has negative x/y; the frame is monitor-local, so subtract the monitor origin only if the incoming coords are global. Document which and test both monitor positions.
- No capture held → error "No capture to crop — start a new snip."
- From T08 (verified by Reviewer against xcap 0.9.10): on Windows, monitor x/y/width/height and Tauri `cursor_position()` are both **physical** px in the virtual desktop. The held frame is monitor-local physical px. So: overlay sends logical px relative to the overlay window; physical = logical × scale; clamp to frame.
